En muchos casos, el primer contacto con WinUI 3 se da a través de ejemplos simples que muestran cómo renderizar una ventana o agregar controles básicos. Este tipo de aproximación es útil para entender la tecnología, pero no prepara al desarrollador para construir aplicaciones reales.

Cuando se inicia un proyecto sin una base sólida, las decisiones iniciales impactan directamente en la capacidad de mantener, escalar y evolucionar la aplicación en el tiempo.
<!--more-->

Este artículo explica cómo construir una primera aplicación en WinUI 3 con un enfoque correcto desde el inicio, evitando errores comunes que generan deuda técnica temprana.

## El problema

El enfoque más común al crear una primera aplicación es seguir el flujo que propone la plantilla por defecto:

- Crear proyecto  
- Modificar MainWindow.xaml  
- Agregar lógica en code-behind  
- Manipular controles directamente  

Este enfoque genera aplicaciones funcionales, pero introduce problemas importantes:

- Acoplamiento fuerte entre UI y lógica  
- Falta de testabilidad  
- Dificultad para escalar funcionalidades  
- Código difícil de mantener  

### Ejemplo incorrecto

```csharp
private void AddItem_Click(object sender, RoutedEventArgs e)
{
    MyListView.Items.Add("Nuevo elemento");
}
```

Problemas:

- No existe separación de responsabilidades  
- No hay control sobre el estado  
- No es reutilizable  
- No permite crecimiento estructurado  

Este tipo de código es aceptable en pruebas rápidas, pero no en aplicaciones reales.

## La solución

La primera aplicación debe construirse con una base estructural correcta, incluso si el alcance funcional es pequeño.

Esto implica:

- Uso de MVVM  
- Separación de capas  
- Manejo explícito del estado  
- Preparación para crecimiento  

## Paso 1: Definir ViewModel desde el inicio

```csharp
using System.Collections.ObjectModel;

public class MainViewModel
{
    public ObservableCollection<string> Items { get; } = new();

    public void AddItem(string item)
    {
        if (string.IsNullOrWhiteSpace(item))
            return;

        Items.Add(item);
    }
}
```

Se observa que la lógica se ubica fuera de la vista.

## Paso 2: Diseñar la vista sin lógica

```xml
<StackPanel Padding="20" Spacing="10">

    <TextBox x:Name="InputText"/>

    <Button Content="Agregar"
            Click="AddItem_Click"/>

    <ListView ItemsSource="{x:Bind ViewModel.Items, Mode=OneWay}" />

</StackPanel>
```

La vista solo define estructura visual.

## Paso 3: Conectar ViewModel correctamente

```csharp
public sealed partial class MainWindow : Window
{
    public MainViewModel ViewModel { get; }

    public MainWindow()
    {
        this.InitializeComponent();

        ViewModel = new MainViewModel();
        this.DataContext = this;
    }

    private void AddItem_Click(object sender, RoutedEventArgs e)
    {
        ViewModel.AddItem(InputText.Text);
    }
}
```

El code-behind se limita a delegar acciones.

## Paso 4: Preparar la aplicación para crecimiento

Incluso una aplicación simple debe estar preparada para evolucionar.

Ejemplo: agregar validaciones o lógica adicional

```csharp
public void AddItem(string item)
{
    if (string.IsNullOrWhiteSpace(item))
        return;

    if (Items.Contains(item))
        return;

    Items.Add(item);
}
```

Esto evita inconsistencias en el estado.

## Paso 5: Introducir comandos (mejora progresiva)

Una evolución natural es reemplazar eventos por comandos.

```csharp
using System.Windows.Input;

public class RelayCommand : ICommand
{
    private readonly Action _execute;

    public RelayCommand(Action execute)
    {
        _execute = execute;
    }

    public event EventHandler CanExecuteChanged;

    public bool CanExecute(object parameter) => true;

    public void Execute(object parameter)
    {
        _execute();
    }
}
```

Uso en ViewModel:

```csharp
public ICommand AddCommand { get; }

public MainViewModel()
{
    AddCommand = new RelayCommand(() => AddItem("Item desde comando"));
}
```

Esto elimina dependencia directa con la vista.

## Buenas prácticas

- Evitar lógica en la vista  
- Mantener ViewModels simples  
- Preparar código para evolución  
- No depender de ejemplos básicos  

## Conclusión

La primera aplicación en WinUI 3 no debe tratarse como un ejercicio trivial. Es el punto donde se define la base arquitectónica que acompañará al proyecto durante todo su ciclo de vida.

Adoptar buenas prácticas desde el inicio permite evitar reescrituras, mejorar la mantenibilidad y facilitar la incorporación de nuevas funcionalidades sin generar complejidad innecesaria.
